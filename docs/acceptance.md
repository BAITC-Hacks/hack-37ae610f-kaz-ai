# Приёмка KAZ-AI по ТЗ «Электрокомплект»

Дата среза текущего аудита: **22.09.2026**. Статусы ниже относятся к этому срезу и
синтетическому демо; они не подтверждают пригодность для закупки по реальным данным.

## Пять обязательных проверок

| Требование ТЗ | Синтетическое демо | Проверка на данных партнёра |
| --- | --- | --- |
| Потребность по артикулу с учётом продаж, остатка, товаров в пути, категории и роста | Автоматический тест меняет каждый вход и проверяет изменение результата. | Требуется подтвердить срок поставки, страховой запас, кратность и остаток на дату среза. |
| Сезонность и устойчивый рост | Тесты сравнивают сезонный товар с простым средним и проверяют влияние роста. | Определение исходных коэффициентов роста и сезонности заказчиком пока не подтверждено; аналитический стенд не применяет их автоматически. |
| Компенсация спроса при отсутствии товара | Тест с 24 днями stockout даёт больший прогноз, чем сырые продажи. | Нужны даты или число дней отсутствия товара по артикулу. Без них расчёт остаётся оценкой с предупреждением. |
| Исключение крупного разового заказа одного клиента | Заказ 900 единиц `DEMO-C017` исключается из регулярного спроса. | Нужен стабильный обезличенный ID клиента в детализации продаж. При его отсутствии возможна только менее точная проверка по документу. |
| Список по поставщикам с объяснением | Работают отдельные карточки поставщиков, объяснения строк и CSV после утверждения. | Нужен полный прогон по согласованному срезу данных и проверка результата закупщиком. |

## Что требуется от заказчика для приёмки реального заказа

1. **Справочник условий закупки:** поставщик, код товара 1С, срок поставки в днях,
   страховой запас в днях или согласованная политика его расчёта, период пересмотра,
   минимальная партия/кратность, дата действия и ответственный за подтверждение.
   Нулевое значение должно быть указано явно, если оно действительно означает ноль.
2. **Остатки:** свободный остаток по коду товара и складу на одну согласованную дату,
   с пояснением, вычтены ли резервы. Для IEK текущий подтверждённый остаток пока не
   установлен. Товары в пути нужны с количеством и ожидаемой датой прихода.
3. **Продажи и дефицит:** обезличенный ID клиента в строке продажи, дата, код товара,
   количество и номер документа; периоды отсутствия товара с датами или числом дней.
   Никакие имена, телефоны и адреса клиентов для расчёта не требуются.
4. **Определения полей:** что означают `Кэф. Роста`, `Кэф. Сез-ти` и категории в
   предоставленной выгрузке. До подтверждения эти значения нельзя трактовать как
   готовые множители заказа.
5. **Формат импорта в 1С:** один обезличенный образец файла заказа либо точное
   описание колонок, кодировки, разделителя, обязательных реквизитов, единиц измерения
   и правил разделения по поставщикам. Текущий CSV — демонстрационный, совместимость
   с конкретным импортом 1С не подтверждена.

По сохранённому [аудиту Systeme Electric](../supply_control/data/analysis/replenishment_core_audit_systeme.json)
все 497 строк заблокированы без срока поставки и страхового запаса; у 28 строк также
нет подтверждённой кратности. Эти числа нужно пересчитать после обновления источников.

## Текущий CSV и критерий завершения

После утверждения синтетической позиции приложение формирует UTF-8 с BOM,
разделитель `;`, заголовки: `Поставщик`, `Код 1С`, `Наименование`, `Количество`,
`Рекомендация`, `Дата среза`, `Горизонт, дни`, `Обоснование`. Это удобный для чтения
экспорт, а не подтверждённый формат загрузки в 1С.

Приёмка завершена, когда на согласованном срезе закупщик может проследить исходные
поля каждой позиции, воспроизвести расчёт, исправить количество с соблюдением
кратности, утвердить заказ, получить отдельный файл поставщика и успешно загрузить
его в тестовый контур 1С. Отправка поставщику возможна только после подтверждения
ответственного сотрудника.
