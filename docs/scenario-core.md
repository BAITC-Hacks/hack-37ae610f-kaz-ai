# Сценарное ядро и происхождение параметров

Хакатонная версия может рассчитывать заказ до получения полного справочника партнёра,
но не должна показывать предположение как подтверждённый факт. Поэтому срок поставки,
страховой запас, MOQ и закупочная цена передаются вместе с метаданными.

## Статусы

| Статус | Значение | Допуск к заказу |
| --- | --- | --- |
| `confirmed` | Значение подтверждено источником | Да |
| `user_input` | Ответственный сотрудник ввёл значение явно | Да |
| `assumption` | Значение используется только для сценария | Нет |
| `missing` | Значение отсутствует | Нет |

Для каждого параметра API возвращает значение, единицу измерения, источник,
уверенность и пояснение. `terms_readiness` имеет один из трёх итоговых статусов:

- `confirmed` — обязательные параметры подтверждены, количество можно вынести на ручное утверждение;
- `scenario` — расчёт выполнен, но содержит предположения;
- `blocked` — одного или нескольких обязательных параметров нет.

Цена не влияет на прогноз количества. Если она задана, ядро возвращает
`order_value = quantity × unit_cost` и отдельный `pricing_status`. В публичном демо
цены вымышлены и всегда помечены как `assumption`.

## Защитные правила

1. Отсутствующие срок поставки, страховой запас и MOQ не считаются подтверждёнными.
2. В партнёрском режиме сценарные и неполные строки нельзя утвердить или выгрузить.
3. Явный ввод сотрудника может разблокировать расчёт, но сохраняет источник `user_input`.
4. Присутствие цены не снимает блокировку обязательных закупочных условий.
5. Сервис не отправляет сформированный заказ поставщику.

Реализация находится в `kaz_ai/parameters.py`, интеграция расчёта — в
`kaz_ai/engine.py`, серверная проверка — в `kaz_ai/server.py`.
