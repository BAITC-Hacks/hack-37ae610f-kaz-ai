# KAZ-AI — рекомендации для заказов поставщикам

Прототип для кейса ТОО «Электрокомплект» на HackAlem AI. Закупщик получает объяснимый прогноз спроса и рекомендуемое количество по артикулу, проверяет его, при необходимости корректирует и утверждает. Публичное демо работает **только с вымышленными товарами, продажами и ID клиентов**. Сервис **не отправляет заказы поставщикам**.

[Техническое задание](https://docs.google.com/document/d/1Z4faOPlT1t6NMCuJSKKB8-vkZ2LVzGMR0PO9rtZgSnM/edit)

## Запуск

Нужен Python 3.11+. Для синтетического режима внешние пакеты не нужны.

```bash
python3 -m kaz_ai
```

Откройте `http://127.0.0.1:8765/`. Без аргументов запускается **синтетический набор**: 12 товаров, 1 537 операций, 5 вымышленных ID клиентов, 32 месяца истории. Продажи с ID клиентов можно скачать из интерфейса или по адресу `/api/synthetic-sales.csv`.

В наборе есть проверяемые сценарии: сезонность, рост, 22 дня дефицита в сентябре 2025 года, товары в пути и заказ 900 единиц клиента `DEMO-C017` в мае 2025 года. Последний исключается из регулярного спроса по товару `DEMO-A202`; это видно в объяснении рекомендации. Один товар специально оставлен без текущего остатка, чтобы показать блокировку количества заказа до ручного ввода.

Для локальной проверки отдельных архивов предусмотрен приватный режим. Архивы должны оставаться вне репозитория; он требует `pip install -r requirements.txt`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m kaz_ai \
  --iek "/путь/к/первому.zip" \
  --systeme "/путь/к/второму.zip" \
  --as-of 2026-09-22
```

Можно передать один архив. `--as-of` — дата среза остатков, а не сегодняшняя дата. Если дата среза отличается от даты остатка, сервис не выдаёт утверждаемое количество до ввода актуального остатка. Интерфейс слушает только `127.0.0.1`; порт меняется через `--port`.

## Методика расчёта

1. История содержит месячные продажи и детальные операции с ID клиента. В синтетическом наборе сумма операций за месяц совпадает с месячными продажами. В базовую историю входят только закрытые месяцы.
2. Разовый крупный заказ ищется по ID клиента; если ID отсутствует, используется номер документа. Событие исключается, только когда его доля велика, месяц выглядит аномальным и сумма деталей согласуется с месячной историей. Дополнительная проверка ограничивает изолированный месячный всплеск; повторяющийся сезонный пик не исключается. В рекомендации указывается ID клиента и исключённое количество.
3. Для месяца с подтверждёнными днями отсутствия товара продажи пересчитываются на доступные дни с ограничением величины оценки. Если точных дней нет, нулевой начальный остаток и низкие продажи дают лишь **помеченную оценку** упущенного спроса.
4. База — среднее скорректированных продаж за последние 12 закрытых месяцев. Сезонный коэффициент рассчитывается из помесячных количеств товара; для разреженной истории он смешивается с профилем категории или поставщика. Устойчивый рост оценивается сравнением последних двух полугодий; при наличии коэффициента роста в источнике оба сигнала смешиваются с ограничением экстремальных значений.
5. Прогноз складывается по дням с сезонным коэффициентом каждого месяца. Целевой период равен **выбранному покрытию + сроку поставки + страховому запасу в днях**. **Потребность = прогноз на целевой период − свободный остаток − товары в пути, прибывающие до конца периода.** Положительная потребность округляется вверх до кратности заказа.
6. Срочность показывает риск нехватки товара до ближайшей поставки: прогноз спроса за срок поставки сравнивается с остатком и поступлениями в этот срок.

Каждая строка показывает прогноз, свободный остаток, ожидаемые поступления, рост, кратность и величину исключённых всплесков или восстановленного спроса. Горизонт 30 дней — **пользовательский сценарий**. В публичном демо сроки поставки (12 и 21 день) и страховой запас (4–7 дней) вымышлены. Для архивов партнёра срок по умолчанию отсутствует и это явно отмечается в рекомендации.

## Ограничения данных

| Поле | Состояние | Поведение прототипа |
| --- | --- | --- |
| ID клиента | Синтетический набор содержит ID у каждой операции | Крупный заказ `DEMO-C017` явно исключён из регулярного спроса. |
| Дни дефицита | В синтетическом наборе для одного месяца задано число дней без товара | Спрос за недоступные дни оценивается с ограничением величины. |
| Сроки поставки и страховой запас | Значения партнёра не предоставлены | В синтетическом примере используются вымышленные сроки и запас. При импорте архивов невыданный срок помечается; даты партий в пути учитываются отдельно. |
| Свободный остаток | Для одного демонстрационного товара отсутствует | Количество заказа скрыто до ручного ввода остатка на дату среза. |
| Формат импорта в 1С | Не предоставлен | CSV содержит код товара и поля заказа; совместимость с конкретным импортом 1С пока не подтверждена. |

Если используются архивы партнёра, их детальные продажи могут не содержать ID клиента и точных периодов дефицита. В этом режиме интерфейс показывает предупреждения, а оценки по неполным данным следует проверять вручную. Денежные агрегаты из вкладок «Сезонность» не подставляются в прогноз **количества**.

## Утверждение и экспорт

Выберите позиции, измените количество с соблюдением кратности и нажмите «Утвердить выбранные». После этого доступен общий CSV или CSV отдельного поставщика в UTF-8 с BOM и разделителем `;`. Карточки поставщиков показывают рекомендованные и утверждённые позиции. Действия закупщика записываются в журнал. В локальном Python-сервисе утверждения, вручную введённые остатки и журнал хранятся в `.local/`, которое исключено из Git. Они привязаны к версии синтетического набора или к конкретным архивам и дате среза. Изменение остатка сбрасывает прежнее утверждение для этого артикула.

## Публичное демо

[Открыть KAZ-AI](https://kaz-ai-hackalem.vercel.app/) — статическая версия только с вымышленными товарами, операциями и ID клиентов. Утверждения, введённые остатки и журнал действий сохраняются в `localStorage` этого браузера. Они не передаются на сервер и не синхронизируются между устройствами. CSV формируется в браузере.

Интерфейс разделён на пять страниц: «Обзор», «Рекомендации», «Поставщики», «История» и «Настройки». На странице «Настройки» можно выбрать русский или казахский язык; выбор сохраняется в браузере. Утверждённые решения доступны после перехода между страницами. Цвета и текстовое название заказчика в шапке отсылают к [сайту ГК «Электрокомплект»](https://nursultan.ekt.kz/). Исходные названия и коды товаров в CSV сохраняются для совместимости с учётными данными.

[Короткое видео демо](docs/demo.webm) показывает выбор поставщика, объяснение рекомендации, утверждение позиции и журнал действий.

Собрать и проверить статическую версию локально:

```bash
python3 -m scripts.build_static_demo
python3 -m http.server 8767 --directory site
```

Публикация текущего содержимого `site/` вручную: `cd site && npx vercel deploy --prod`. Автоматическая публикация изменений из Git пока не настроена.

## Проверка прогноза

```bash
python3 -m kaz_ai.backtest
```

[Отчёт](reports/backtest.md) содержит воспроизводимый помесячный бэктест за январь 2025 — август 2026: 240 прогнозов, WAPE 9,1% против 19,9% у простого среднего сырых продаж за последние 12 месяцев. Для каждого прогноза используются только месяцы, завершённые к дате расчёта. Проверка выполнена **исключительно на сконструированных синтетических сценариях**; она не показывает ожидаемую точность на данных партнёра.

## Проверка требований

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют влияние входных факторов на результат, сезонность и рост, восстановление спроса при дефиците, исключение крупной покупки одного клиента, согласованность синтетических операций с месячными продажами, группировку по поставщику, срок и страховой запас, MOQ, утверждение и журнал действий.

Исходные Excel и ZIP в репозиторий не добавляются. Для развёртывания за пределами локального компьютера потребуется отдельная проверка защиты данных, пользователей и формата интеграции с 1С.
