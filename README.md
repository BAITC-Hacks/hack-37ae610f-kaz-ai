# KAZ-AI — рекомендации для заказов поставщикам

Прототип для кейса ТОО «Электрокомплект» на HackAlem AI. Закупщик получает объяснимый прогноз спроса и рекомендуемое количество по артикулу, проверяет его, при необходимости корректирует и утверждает. Сервис **не отправляет заказы поставщикам**.

[Техническое задание](https://docs.google.com/document/d/1Z4faOPlT1t6NMCuJSKKB8-vkZ2LVzGMR0PO9rtZgSnM/edit) · [Архив ИЭК](https://drive.google.com/file/d/18AqNcbkaqrvoLuX9fPsLMleEj7g6CWFb/view) · [Архив Systeme electric](https://drive.google.com/file/d/1CkzeElvVm_YwkFCofXX1MGBJuUjMecTz/view)

## Запуск

Нужен Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m kaz_ai
```

Откройте `http://127.0.0.1:8765/`. Без аргументов запускается небольшой **синтетический пример**. Он не содержит данных партнёра.

Для двух предоставленных архивов сохраните ZIP вне репозитория и запустите:

```bash
.venv/bin/python -m kaz_ai \
  --iek "/путь/к/IEK.zip" \
  --systeme "/путь/к/Systeme electric.zip" \
  --as-of 2026-09-22
```

Можно передать один архив. `--as-of` — дата среза остатков, а не сегодняшняя дата. Если дата среза отличается от даты остатка, сервис не выдаёт утверждаемое количество до ввода актуального остатка. Интерфейс слушает только `127.0.0.1`; порт меняется через `--port`.

## Методика расчёта

1. Импорт связывает детальные продажи, месячные продажи и остатки, MOQ и товары в пути по коду 1С. Сентябрь 2026 года в этих выгрузках неполный, поэтому в базовую историю входят только закрытые месяцы.
2. Разовый крупный заказ ищется по документу или обезличенному ID клиента, если он появится в данных. Событие исключается, только когда его доля велика, месяц выглядит аномальным и сумма деталей согласуется с месячной выгрузкой. Дополнительная проверка ограничивает изолированный месячный всплеск; повторяющийся сезонный пик не исключается.
3. Для месяца с подтверждёнными днями отсутствия товара продажи пересчитываются на доступные дни с ограничением величины оценки. Если точных дней нет, нулевой начальный остаток и низкие продажи дают лишь **помеченную оценку** упущенного спроса.
4. База — среднее скорректированных продаж за последние 12 закрытых месяцев. Сезонный коэффициент рассчитывается из помесячных количеств товара; для разреженной истории он смешивается с профилем категории или поставщика. Устойчивый рост оценивается сравнением последних двух полугодий; при наличии коэффициента роста в источнике оба сигнала смешиваются с ограничением экстремальных значений.
5. Прогноз на выбранный горизонт складывается по дням с сезонным коэффициентом каждого месяца. **Потребность = прогноз − свободный остаток − товары в пути, прибывающие до конца горизонта.** Положительная потребность округляется вверх до кратности заказа.

Каждая строка показывает прогноз, свободный остаток, ожидаемые поступления, рост, кратность и величину исключённых всплесков или восстановленного спроса. Горизонт 30 дней — **пользовательский сценарий**, а не установленный партнёром срок поставки.

## Ограничения текущих выгрузок

| Поле | Состояние | Поведение прототипа |
| --- | --- | --- |
| Обезличенный ID клиента | В детальных продажах отсутствует | Крупные разовые заказы ищутся по документу и месячному всплеску; сценарий с ID клиента проверяется синтетически. |
| Точные периоды stockout | Отсутствуют | Нулевые начальные остатки дают оценку с предупреждением; точный сценарий проверяется синтетически. |
| Сроки поставки поставщика | Нет справочника | Горизонт задаёт закупщик; даты уже отправленных партий учитываются отдельно. |
| Текущий свободный остаток ИЭК | В архиве есть месячный начальный остаток, но нет подтверждённого остатка на дату среза | Спрос прогнозируется, количество заказа скрыто до ручного ввода свободного остатка на дату среза. |
| Категории | Есть в сводной таблице Systeme electric, для ИЭК отсутствуют | Для ИЭК используется сезонный профиль поставщика. |
| Формат импорта в 1С | Не предоставлен | CSV содержит код 1С и поля заказа; совместимость с конкретным импортом 1С пока не подтверждена. |

Вкладки «Сезонность» содержат агрегаты в денежном выражении. Для прогноза **количества** используется помесячная история по артикулам; денежные агрегаты доступны для отдельной сверки и не подставляются в количественный прогноз.

## Утверждение и экспорт

Выберите позиции, измените количество с соблюдением кратности и нажмите «Утвердить выбранные». После этого доступен CSV в UTF-8 с BOM и разделителем `;`. Утверждения и вручную введённые остатки хранятся локально в `.local/`, которое исключено из Git. Они привязаны к конкретным исходным архивам и дате среза. Изменение остатка сбрасывает прежнее утверждение для этого артикула.

## Проверка требований

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты проверяют влияние входных факторов на результат, сезонность и рост, восстановление спроса при stockout, устойчивость к крупной покупке одного клиента, группировку по поставщику, объяснение строки, MOQ и подтверждение сотрудником. Для демонстрации на данных партнёра загрузите оба ZIP и снимите фильтр «Только к заказу», чтобы увидеть позиции без текущего остатка.

Исходные Excel и ZIP в репозиторий не добавляются. Для развёртывания за пределами локального компьютера потребуется отдельная проверка защиты данных, пользователей и формата интеграции с 1С.
